# Архитектура MVP

## Поток

`orders → ride → event → ride → result → orders / garage`

Контроллер main.gd управляет экраном. GameState не зависит от дерева сцены: его можно проверять headless с фиксированным seed. City отвечает за изображения и столкновения и передаёт сигнал hit; расчёт урона остаётся в GameState.

События описываются данными: id, минимальный риск и варианты с chance/effect/failure. Эффекты поддерживают time, distance, damage, pay, rep, sell, item и fail. Выбор доступен один раз; симуляция при выборе и паузе остановлена.

## Контент

- Заказ: добавьте строку со стабильным ID в Catalog.ORDERS. Предложения выбираются по трём категориям риска и вместимости.
- Событие: добавьте encounter() в Catalog.events(). Для нового типа эффекта расширьте GameState.apply_effect() и добавьте тест последствий.
- Предмет: добавьте название в ITEMS; уже выпавшие предметы используют индекс, поэтому существующие строки нельзя переставлять. Для большего каталога следующая миграция должна перейти на строковые ID.
- Транспорт: добавьте VEHICLES; назначьте новую модель в City.set_vehicle(). Для старых сохранений необходима миграция новых upgrade-записей.
- Район: каталог готов к расширению, но в MVP генерация использует suburb. Следующий этап — поле открытых районов в профиле, выбор района в UI и передача traffic/reward в генератор.

## Сохранение

Схема version=1. Профиль содержит банк, рискованный доход смены, серию, транспорт, уровни улучшений, репутации и коллекцию. Сначала пишется .tmp, предыдущий валидный файл становится .bak, затем переименовывается новый файл. Повреждённый основной файл не заменяет валидную резервную копию.

Перед поездкой записывается active_delivery. При следующем запуске незавершённая поездка обнуляет доход смены, но сохраняет банк и покупки. Награды не начисляются дважды: settle() очищает run. Предметы из событий сначала остаются в run и попадают в профиль только при успехе.

Это локальное сохранение, не облачная синхронизация и не защита от редактирования файлов. При изменении схемы нужно добавить миграции, а не молча сбрасывать прогресс.

## Проверки и границы

Тесты покрывают уникальность и доступность предложений, вместимость, выплаты, банковский баланс, провал, покупки, уровни, нитро, урон, границы полос, события, резервную копию, прерванную поездку, навигацию экранов и синтетический свайп. Захват изображений выполняется отдельным процессом с реальным OpenGL-рендерером.

Полноценная физика, реалистичные отражения, сервер, реклама, платежи и бизнес-симуляция не добавлены. Для мобильной производительности используются Compatibility, одна фара и простые mesh-объекты. Профилирование на устройствах остаётся обязательным перед релизом.
